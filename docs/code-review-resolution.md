## 已确认的历史数据边界

旧版无 `source` 的超时限制只有在原验证行仍为 `restricted`、且限制的 `event_id` 与原验证 token 相同时，才会在重触发时补充来源标记。如果原验证行已经丢失，重触发验证通过后仍会保留该限制，不恢复发言权限。此情况已用临时 SQLite 数据库复现，尚未修复。当前定时清理会保留 `restricted` 验证行；该问题涉及历史清理、手动删除或已有孤立记录，需要额外的来源判定才能安全处理，不能直接把无标记的限制一律视为验证超时。
